Achados de maior severidade (verificados linha a linha nesta consolidação)

SEC-01

Empresa é "autenticada" só pelo CNPJ — empregabilidade_engine.py:753,761-767. CNPJ não é segredo (nota fiscal, contrato, busca pública) — qualquer conversa que informe os 14 dígitos de uma empresa já cadastrada recebe a identidade completa dela pro resto da sessão. Fluxos de edição/cancelamento filtram por empresa_id, mas esse ID só vale o que vale essa checagem — nada. Cancelamento é irreversível pelo próprio texto do bot.

Plano: plans/empregabilidade/001-sec01-autenticacao-empresa-por-cnpj.md

SEC-02

Consulta de candidatura vaza dado de terceiro — empregabilidade_engine.py:1298-1352. As 4 estratégias de busca (CPF, código, telefone, nome) usam o valor digitado na mensagem, nunca o phone real de quem manda — já disponível como parâmetro da função. Qualquer um que saiba nome/telefone de um candidato puxa status e observações internas do recrutador.

Plano: plans/empregabilidade/002-sec02-consulta-candidatura-vaza-dado-terceiro.md

BUG-01

aguardando_retorno_selecao sem handler síncrono — empregabilidade_engine.py:1034-1045,1113-1115. As 2 etapas irmãs tratam mensagem manual do usuário enquanto aguardam o portal; esta não — cai no fallback genérico que reseta a empresa inteira pra "informe seu CNPJ". O loop de notificação assíncrono já cobre esta etapa — o gap é só a mensagem manual síncrona.

Plano: plans/empregabilidade/003-bug01-aguardando-retorno-selecao-sem-handler.md

BUG-02 / PERF-01

~48 chamadas Supabase síncronas dentro de async def — asyncio.to_thread aparece 1x no arquivo inteiro; supabase.table( aparece 49x. Cada chamada trava o event loop inteiro (todas as conversas), não só a de quem está sendo atendido. Esforço L — melhor via helper _exec() aplicado sistematicamente. Sem plano formal ainda; recomendo TEST-01/#14 antes.

TEST-01

Zero teste nos 3 fluxos de maior risco — cancelamento de vaga (irreversível), cadastro de empresa, confirmação de entrevista. Grep confirma zero ocorrência desses nomes de etapa nos testes. Sem plano formal ainda.

EMP-01

Filtro de setor por substring — intencao_detector.py:270-285. "entrega" (Logística) casa dentro de "entregar" — "Quero entregar meu currículo" filtra silenciosamente só vagas de Logística. Mesma classe já corrigida no Institucional (AUD-05), nunca aqui. Teste local: test_entregar_curriculo_nao_deveria_disparar_filtro_de_logistica.

EMP-02 (= achado #8)

"Quer encerrar" substring sem limite de palavra — empregabilidade_engine.py:191-193, checado em 3 fluxos, sem exceção nenhuma no fluxo candidato (e roda antes do próprio escape semântico daquele fluxo). "Muito obrigado! mas ainda tenho uma dúvida" encerra a conversa sem aviso. Teste local: TestQuerEncerrarSubstringSemLimiteDePalavra.

EMP-03

Negação ignorada em pos_candidatura — :1585-1601. "Não quero mais vagas" contém "quero" → lido como pedido de mais vagas. A etapa vizinha já tem a correção certa, não foi replicada. Teste local: TestPosCandidaturaNegacaoIgnorada.

EMP-04

menu_pos_vaga reinterpreta resposta contra menu errado — :1101-1106. Menu real é "1=nova vaga/2=consulta/3=editar/4=cancelar" (não "3=Encerrar" como o texto mostrado sugere) — responder "3" achando "Encerrar" cai em editar vaga. Teste local: TestMenuPosVagaReinterpretaResposta.
